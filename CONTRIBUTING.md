# Contributing a style

Keep skills independently installable. A short frontmatter description should distinguish each style. Put tool-specific procedures in linked references. Examples must run without private infrastructure; identify optional runtime dependencies.

Show a realistic explanation and document what was rendered, inspected, or unverified. Test reusable scripts with invalid as well as valid input. Do not bundle credentials, private work, unlicensed reference media, voice recordings, or imitation profiles. Use original assets and licensed dependencies.

Improve decisions on real tasks rather than adding universal rules from unusual examples. More styles are welcome: whiteboard explanations, data stories, typography-led updates, and others can have their own skills when useful guidance justifies them.
